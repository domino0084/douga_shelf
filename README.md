# DougaShelf（ドウガシェルフ）

## 1. サービス概要

- YouTubeの動画をURLの貼り付けだけで登録し、自分で決めたカテゴリとタグで整理できるサービスです。
- 複数の分野をYouTubeで学んでいる人が、カテゴリとタグの組み合わせやフリーワードで、チャンネルをまたいで目当ての動画をすぐに見返せるようにします。
- 登録時の入力はURLだけで、カテゴリとタグは後から付けられます。

---

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情

IT・AI・健康・副業など複数の分野をYouTubeで学んでおり、後から見返したい動画をエクセルで管理しています。
列は「URL・タイトル・動画カテゴリ・登録日・タグ・備考」の6つです。
エクセルのフィルターでカテゴリ別に絞り込んだり、タグで絞り込んで異なるチャンネルの同じテーマの動画を一覧にしたりして使っています。

この管理自体は役に立っていますが、動画を1本登録するたびにURLとタイトルを貼り付け、カテゴリやタグを入力する作業が面倒に感じています。

エクセルでの管理は約1年前に始め、現在は約100件の動画を登録しています。

特に面倒だと感じるのは、カテゴリとタグを付ける作業です。
URLとタイトルは貼り付けるだけで済みますが、カテゴリとタグは1本ごとに「どの分類にするか」「過去にどんなタグを使ったか」を考えて入力しなければなりません。
動画を見つけてすぐに登録したいのに、この分類の作業で手が止まってしまい、登録そのものが億劫に感じるようになりました。

### 2-2. なぜそれが「気になった」のか

自分は、一つの作業に時間がかかりすぎると嫌になってしまう性格です。
過去にも、情報を整理しようと管理を始めたものの、更新に手間がかかって続かず、結局そのままになってしまった経験があります。

動画の管理も、登録の手間が大きいままだと同じように更新しなくなり、せっかく1年かけて作った一覧が使えなくなってしまうのではないかと感じました。
「続けられる手軽さ」がないと管理は破綻する、という実感があるため、この手間が気になりました。

## 3. 課題の整理

### 3-1. 表に見えている困りごと

動画をエクセルに登録する手間が大きいこと。
1本ごとにURL・タイトル・カテゴリ・タグなど複数の項目を手で入力する必要があり、特にカテゴリとタグを毎回考えて入力する作業が負担になっています。

### 3-2. 本当に解決したい課題は何か

- なぜ困るのか①：登録に手間がかかるため、動画を見つけたその場で登録するのが負担になる。
- なぜ困るのか②：整理されていないと、必要なときに目当ての動画が見つからず、YouTube内で探し直すことになる。
- なぜ困るのか③：探し直しに時間がかかると、見た動画の知識を再利用できず、見ただけで終わってしまう。

→ 本当に解決したい課題：複数のチャンネルから得た知識を、自分のテーマ単位で後から引き出せる状態を、手間なく保ち続けられないこと。

## 4. 想定ユーザーについて

### 4-1. 想定しているユーザー

システムエンジニアとして働きながら、複数の分野（IT・AI・健康・副業など）をYouTubeで独学している50歳の社会人。登録チャンネルが多く、テーマごとに動画を見返す習慣がある。（自分自身です）

年齢設定：

- 年齢：50歳
- 理由：仕事で必要な技術の学び直しに加えて、健康や副業など関心が複数の分野に広がっており、分野をまたいで動画を整理する必要性が高いため。また、仕事と並行して学ぶので使える時間が限られ、「探し直す時間」と「登録にかかる時間」の両方を減らす価値が大きいため。

生活・状況設定：

- 生活・状況：YouTubeでRUNTEQの動画をはじめ様々な動画を視聴している。あとで見返したいときに、登録チャンネル・カテゴリ・タグなど自分の軸で動画を探せないのが不便で、エクセルで管理している。しかし登録に手間がかかり、不便に感じている。
- 理由：学んだ内容を仕事や生活で使う場面で「あの動画をもう一度見たい」となったとき、テーマで絞り込めばすぐに見つかる。

環境設定：

- 環境：PCのブラウザでYouTubeを視聴している。スマートフォンでの利用は本リリースで対応する想定
- 理由：視聴中のタブからURLをコピーして貼り付けるだけで登録できるため、PCでの視聴の流れを止めない。

### 4-2. 自分とユーザーの距離

自分自身。

現在エクセルで同じ管理をしており、登録の手間と、テーマで横断して見返す使い方の両方を日常的に経験しているためです。

### 4-3. 実際に使われる可能性について

- 最初に使ってくれそうな人：自分自身。次に、YouTubeで学習しているスクールの受講生。
- このアプリを思い出す場面：後で見返したい動画を見つけたとき。あるテーマについて過去に見た動画を探したいとき。
- 今、代わりに使っているもの：エクセル。一般的にはYouTubeの再生リストや「後で見る」。
- 置き換えてまで使う理由：エクセルは絞り込みはできるが登録が手入力。再生リストは登録は簡単だが、カテゴリとタグを組み合わせた絞り込みや備考の記録ができない。登録の簡単さと絞り込みの両方を満たすものがない。

### 4-4. ユーザーがサービスを導入して利用するまでのイメージ

- きっかけ：「後で見る」や再生リストが増えすぎて目当ての動画が見つからない、または自作の表での管理が面倒になったとき。
- 最初の一歩：ユーザー登録をして、動画のURLを1つ貼り付ける。タイトルとチャンネル名が自動で入り、登録が完了する。
- 利用を続ける理由：登録した動画が増えるほど、テーマで横断して見返せる自分専用の一覧として価値が上がる。カテゴリやタグを後から付けられるので、登録だけ先に済ませて整理を後回しにできる。

## 5. 既存サービス・競合調査

### 5-1. 似たサービスの調査

#### VideoTag

- サービス名：VideoTag
- URL：https://apps.apple.com/jp/app/id6444388165
- どんなことができるか：iOSアプリ。YouTubeなどの動画アプリの共有メニューから動画URLを送り、ハッシュタグを付けて保存・管理できる。

#### YouTubeの再生リスト／「後で見る」

- サービス名：YouTubeの再生リスト／「後で見る」
- URL：https://www.youtube.com/
- どんなことができるか：動画をリストに追加して保存できる。

#### VideoTagを実際に使ってみた感想

- 良かった点：動画アプリから共有するだけで登録される。タグも自動で付与される。
- 合わなかった点：カテゴリがなく、カテゴリとタグを組み合わせた絞り込みができない。フリーワードでの検索ができない。メモを入力できる箇所を見つけられなかった。PCで使えない。

※自分が使った範囲での感想です。

### 5-2. それでも自分が作りたい理由

VideoTagは「登録の手軽さ」は優れていて、共有するだけで登録され、タグまで自動で付く点は自分のエクセル管理よりずっと楽でした。

しかし、自分が動画を管理している目的は「保存すること」ではなく「後からテーマで探し出すこと」です。
VideoTagではタグでの絞り込みはできましたが、カテゴリがないため「カテゴリで大きく分けてからタグで絞る」という、自分がエクセルで行っている探し方ができませんでした。
フリーワードでの検索もできないため、タグを付け忘れた動画やタイトルの一部しか覚えていない動画を探せません。
メモを入力できる箇所も見つけられず、なぜその動画を保存したのかを記録できませんでした。
また、自分はPCで動画を見ることが多いのに、PCから使えない点も合いませんでした。

YouTubeの再生リストも、リストに入れることはできても、カテゴリとタグを組み合わせて絞り込んだり、備考を残したりすることはできません。

つまり、既存のものは「登録は簡単だが、自分の探し方では探しきれない」か、エクセルのように「探せるが登録が面倒」のどちらかでした。
登録の手軽さと、後から探し出せることの両方を満たすものが欲しいというのが、自分で作りたい理由です。

### 5-3. 差別化を「体験価値」で表現する

- 私のアプリの差別化ポイント：複数分野をYouTubeで学ぶ人が、動画を見つけたその瞬間にURLを貼るだけで保存でき、後から「カテゴリ×タグ」の組み合わせやフリーワードで、チャンネルをまたいで目当ての動画にたどり着ける。

### 6-1. ユーザーの変化

- 行動の変化：見返したい動画を、見つけたその場で登録するようになる。探すときはYouTube内の検索ではなく、自分の一覧をテーマで絞り込む。
- 気持ちの変化：「あの動画どこだっけ」という探し直しのストレスがなくなる。

このサービスは、複数分野をYouTubeで学ぶ人が、チャンネルをまたいでテーマ別に動画をすぐ見返せるようになるサービス。

## 7. このアプリで実現すること

### MVPで作る機能

- ユーザー登録・ログイン
- 動画の登録：URLを貼り付けると、タイトル・チャンネル名・サムネイルを自動取得して保存する（必須入力はURLのみ）
- 動画の整理：カテゴリ・タグ・備考を後から追加、編集できる。カテゴリとタグは、過去に使ったものから選んで付けられる
- 動画の一覧と絞り込み：カテゴリとタグを組み合わせて絞り込める。タイトル・備考をフリーワードで検索できる。未分類の動画だけを表示できる

### 本リリースで作る機能

- 既存のエクセル（CSV）からの一括取り込み
- 投稿者が設定したタグを候補として表示（YouTube Data APIを使用）
- ブラウザ拡張またはブックマークレットによるワンクリック登録
- 視聴済み・未視聴の管理
- スマートフォンでの利用への対応
- テスト、CI、エラー監視などの品質面の整備

## 8. このアプリの懸念点とその対策

### 懸念点①

- 何が問題になりそうか：結局エクセルの方が早いと感じ、使われなくなる。
- なぜそう思うか：エクセルは慣れており、一覧性とフィルターの自由度が高いため。
- そのために考えている対策：登録の入力をURLだけにし、カテゴリとタグは後から既存のものを選んで付けられるようにして、エクセルより明確に手間が少ない状態を作る。MVPを自分で毎日使い、エクセルに戻りたくなる場面をIssueに記録して改善する。

### 懸念点②

- 何が問題になりそうか：すでにエクセルにある動画を移行する手間が大きく、使い始められない。
- なぜそう思うか：既存の登録件数が多いほど、1件ずつ登録し直すのは現実的でないため。
- そのために考えている対策：本リリースでCSVの一括取り込みを用意する。MVPの期間は新しく見つけた動画から登録を始める。

### 懸念点③

- 何が問題になりそうか：動画情報の自動取得に失敗する動画がある。
- なぜそう思うか：非公開や削除済みの動画などは情報を取得できない可能性があるため。
- そのために考えている対策：実装前の技術検証で失敗時の挙動を確かめる。取得に失敗した場合は、タイトルを手入力して登録できるようにする。

## 10. 技術スタック

### 10-1. 使用予定の技術

- フレームワーク：Ruby on Rails 8.1系。パッチバージョンは環境構築時に最新のものを確認する
- 言語：Ruby 3.4系（Rails 8.1の動作要件はRuby 3.2以上。3.2はすでにサポートが終了しているため、通常メンテナンス中の3.4系を使う）
- DB：PostgreSQL（本番はNeonのFreeプラン）
- デプロイ先：Render（Freeのweb service）
- 認証：Rails 8標準の認証ジェネレーター（`bin/rails generate authentication`）
- テスト：RSpec・FactoryBot（本リリースで整備）
- 外部の仕組み：YouTubeのoEmbed（動画タイトル・チャンネル名・サムネイルの取得）
- 開発環境：Docker（WSL上）

### 10-3. キャッチアップ不足の懸念

MVPは学習済みのRailsを中心に構成し、新しく調べる必要がある要素を次の4つに絞ります。

1. Rails 7.0と8.1の差分（標準の構成や初期設定の違い）
2. Rails 8標準の認証ジェネレーターと、ユーザー登録の自作
3. oEmbedによる動画情報の取得
4. RenderとNeonへのデプロイ

実装に入る前に、不安の大きい「oEmbedでタイトルを1件取得できるか」と「空のRails 8.1アプリをRenderとNeonにデプロイできるか」を技術検証します。
Reactは受講済みですが、MVPでは画面をRailsのビューで作り、まず価値の検証を優先します。ReactとYouTube Data APIは、本リリース後に必要性を判断して導入を検討します。
